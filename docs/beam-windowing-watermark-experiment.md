# Apache Beam 窗口与水位线实验：跨境贸易实时风控

> **项目**: beam-streaming-poc
> **场景**: 基于 Apache Beam 的跨境贸易实时风控监控系统 POC
> **目标**: 深入理解 Fixed Window、Sliding Window、Session Window 与 Watermark 机制

---

## 1. 业务背景

某银行监控其企业客户的**跨境贸易交易**，需要实时检测是否存在异常交易行为（超额交易、可疑密集交易等）。不同国家的分行上报交易数据存在不同程度的网络延迟，需要合理处理**乱序数据**和**迟到数据**。

### 1.1 数据模型

每条交易记录包含以下字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `transaction_id` | `str` | 交易唯一 ID，格式如 `TXN-{uuid}` |
| `account_id` | `str` | 企业账号，如 `CORP-ALPHA` |
| `amount` | `float` | 交易金额（USD） |
| `trade_type` | `str` | 交易类型：`import`（进口）/ `export`（出口） |
| `counterparty` | `str` | 对手方国家代码，如 `HK`、`SG`、`UK`、`US` |
| `event_timestamp` | `int` | 事件时间（Unix 毫秒），交易实际发生时间 |
| `processing_delay` | `int` | **模拟的迟到延迟（秒）**，用于测试 Watermark 行为 |

### 1.2 数据来源模拟

四种来源地区，模拟不同程度的网络延迟：

| 来源地区 | 代码 | 模拟延迟 | 含义 |
|---------|------|---------|------|
| 🇭🇰 香港分行 | `HK` | 0~1s | 低延迟，实时上报 |
| 🇸🇬 新加坡分行 | `SG` | 2~5s | 中等延迟 |
| 🇬🇧 伦敦分行 | `UK` | 8~15s | 高延迟，跨时区 |
| 🇺🇸 纽约分行 | `US` | 20~30s | 重度延迟，可能产生迟到数据 |

### 1.3 报警机制

在每个窗口内，按 `account_id` 分组聚合累计交易额，超出阈值则触发报警：

| 级别 | 阈值 | 颜色标识 | 处理建议 |
|------|------|---------|---------|
| 🟢 正常 | `≤ $100,000` | 绿色 | — |
| 🔶 关注 (YELLOW) | `$100K ~ $500K` | 黄色 | 需关注，标记风控审查 |
| 🔴 紧急 (RED) | `> $500,000` | 红色 | 紧急风控，临时冻结 |

## 2. 窗口实验设计

### 2.1 Fixed Window（固定窗口）—— 时段结算

```
窗口大小: 30 秒
特性: 不重叠，每笔交易属于唯一窗口
用途: 精确的时段结算
```

**业务含义**：每 30 秒统计一次「过去 30 秒内各账号的累计交易额」，适合做**整点结算报告**。

**示例**：
```
窗口 [12:00:00 ~ 12:00:30)
  ├─ CORP-ALPHA: $245,000 → 🔶 YELLOW
  ├─ CORP-BETA:  $523,000 → 🔴 RED
  └─ CORP-GAMMA: $52,000  → 🟢 OK

窗口 [12:00:30 ~ 12:01:00)
  ├─ CORP-ALPHA: $32,000  → 🟢 OK     ← 清账重算
  └─ CORP-BETA:  $68,000  → 🟢 OK
```

---

### 2.2 Sliding Window（滑动窗口）—— 滚动风险敞口

```
窗口大小: 30 秒
滑动间隔: 10 秒
特性: 窗口重叠，同一笔交易可落入多个窗口
用途: 滚动趋势监控
```

**业务含义**：每 10 秒查看一次「过去 30 秒内的风险敞口」，监控**持续性风险趋势**。

**示例**：
```
窗口 [12:00:00 ~ 12:00:30) → CORP-ALPHA: $140K → 🔶 报警
窗口 [12:00:10 ~ 12:00:40) → CORP-ALPHA: $140K → 🔶 再次报警 ← 同一笔交易还在
窗口 [12:00:20 ~ 12:00:50) → CORP-ALPHA: $60K  → 🟢 OK     ← 首笔交易已滑出
```

> **关键洞察**: 连续多个窗口报警 = 账号长时间处于高风险状态；一过性报警 = 窗口边界效应。

---

### 2.3 Session Window（会话窗口）—— 可疑密集交易检测

```
会话间隙 (Gap Duration): 15 秒
特性: 动态伸缩，同一 Key 在 Gap 内的交易自动合并为一个 Session
用途: 异常行为检测（反洗钱、突击交易）
```

**业务含义**：同一账号在短时间内密集交易 → 合并为一个「交易会话」→ 累计金额超阈值 → 🚨 可疑交易报警。

**示例**：
```
同一账号 CORP-ALPHA:

[10:00:01] $40K  ─┐
[10:00:05] $30K  ─┤ 间隙 < 15s
[10:00:09] $35K  ─┤
[10:00:12] $50K  ─┘
───────────────────────── Session A: $155K 🔴 RED 🚨

         ↓ 安静了...

[10:05:30] $10K  ─┐ 间隙 > 15s → 新 Session
───────────────────────── Session B: $10K 🟢 OK
```

> **关键洞察**: Session Window 能自动发现「突击交易」模式。正常企业的交易分散在不同的会话中，而可疑账户往往在短时间内密集交易形成**长会话 + 高累计**。

## 3. Watermark（水位线）实验

### 3.1 概念回顾

Watermark 是 Beam 对「某个时间点之前的数据是否已经全部到达」的推测：

```
Watermark = T  →  意味着 Event Time < T 的数据理论上已经到齐
Event Time ≥ T → 还在等待中
Event Time < T 但还没到 → 被标记为 Late Data
```

### 3.2 实验设计

利用四种来源地区的不同延迟，观察 Watermark 的变化：

```
时间轴 →
                                                      Watermark 推进
                                                     ────────────→
香港交易 ───●─────────●───────●─────────────────────────  延迟低，准时到
新加坡 ────────●─────────●───────●─────────────────────  稍晚但不迟到
伦敦 ────────────────●───────────────●────────────────  跨时区，接近边界
纽约 ────────────────────────●───────────────●───────  × 可能迟到！
                              ↑                       ↑
                          交易时间戳                Watermark 已过
```

### 3.3 Allowed Lateness（允许迟到）

通过设置 `.withAllowedLateness(Duration.standardMinutes(1))`，给迟到数据一个**宽限期**：

| 策略 | 行为 |
|------|------|
| `AllowedLateness(0)` | Watermark 过后的迟到数据**直接丢弃** |
| `AllowedLateness(60s)` | 迟到的交易如果在 60 秒内到达，仍被纳入对应窗口重新计算 |
| `AllowedLateness(∞)` | 永远等待（慎用，会导致状态无限膨胀） |

### 3.4 Trigger（触发器）实验

丰富的触发策略，控制结果输出时机：

| 触发策略 | 区间 | 含义 |
|---------|------|------|
| **默认 (Watermark)** | — | 只在 Watermark 到达后输出一次 |
| **Early + OnCount** | 每 2 笔 | 每收集 2 笔交易就提前输出一次阶段性结果 |
| **Early + Aligned** | 每 5 秒 | 每 5 秒输出一次当前进度 |
| **Late + After** | 每来 1 笔 | 迟到数据到达后，每笔都更新结果 |
| **Accumulating** | — | 累计模式，每次触发都包含历史所有数据 |
| **Discarding** | — | 丢弃模式，每次触发只输出本轮新增数据 |

## 6. 学习要点总结

| 概念 | 一句话理解 |
|------|-----------|
| **Fixed Window** | 准时段的「快照结算」 |
| **Sliding Window** | 滚动的「风险敞口」 |
| **Session Window** | 动态的「行为检测」 |
| **Watermark** | Beam 的「时间裁判」 |
| **Late Data** | 迟到的「事后诸葛」 |
| **Trigger** | 输出的「扳机」 |
| **Allowed Lateness** | 给迟到的「最后通牒」 |
